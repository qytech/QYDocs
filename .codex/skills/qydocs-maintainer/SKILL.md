# QYDocs 文档维护

## 输入与阅读

1. 遵循根 [AGENTS.md](../../../AGENTS.md)；已在上下文中的内容按其复用规则处理。
2. 确定目标模块、任务类型及事实来源；版本、日期、Maven 坐标、API 签名、兼容性须可核实，缺项按根规则处理。
3. 阅读目标模块全文、根 `README.md` 和相邻模块写法（新增时选择结构接近者），定位独立日志及重复事实。
4. 所有文档任务必须读取 [写作规范](references/style-guide.md) 的“通用格式”；新增或重构主文档、涉及 Android 示例时，再读取对应章节。版本及首页规则以本文件为唯一来源。

## 执行

- **更新版本**：新记录置顶，版本用小写 `v`、日期用 `YYYY-MM-DD`；只记录实际新增、变更、修复，不扩大结论。破坏性变化、迁移步骤、默认值变化单独说明；历史缺失日期不推测。每条用明确动词表达一个可验证变化。
- **新增模块**：主文档为 `docs/<Module>/index.md`，沿用目录大小写；独立日志可用 `CHANGELOG.md`，仅确有独立快速接入场景才加模块级 `README.md`。不创建空章节；已发布 Maven Central 时沿用现有徽章格式。
- **补充或重构**：示例最小且可复制，明确初始化、监听、控制、释放顺序；清楚说明适用的 JNI、线程、权限、ABI、minSdk 和资源释放约束。
- **审查**：核对重复事实（版本、日期、坐标、API 名称及参数单位）、凭据占位、权限与资源释放、链接、围栏和标题；报告文件与行号，仅用户要求修改时编辑。
- **新增或更新模块均须同步**：依赖示例、模块最新版本、独立日志（如有），以及根 `README.md` 的导航链接、Maven 坐标、能力摘要、导航行最后更新日期、仓库最后更新时间。首页日期反映文档更新，不能替代发布日期。

## 验收

在仓库根运行 `python .codex/skills/qydocs-maintainer/scripts/validate_docs.py`，再检查 `git diff --check` 和 `git diff`，确认无意外历史改写。

脚本 `ERROR` 必须修复；本次修改区域的 `WARN` 必须修复，其他历史警告在交付时说明。用 `rg` 核对涉及的版本、日期、坐标或 API 的所有同步位置；旧版本与日期仅可保留在适用的历史内容中。交付修改、验证结果和待确认信息；校验通过不代表 SDK 运行验证通过。
