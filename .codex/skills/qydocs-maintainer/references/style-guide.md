# QYDocs 写作规范

## 通用格式

- 面向 Android 集成工程师，简洁说明能力、接入和限制；技术标识用反引号。避免营销式措辞，无明确依据不写“完美”“完整支持”“零延迟”等绝对结论。
- 每文件一个一级标题，章节从二级开始；标题普通标点不转义，前后留空行。无序列表用 `-`，步骤用有序列表。
- 代码围栏语言标识小写，如 `kotlin`、`groovy`、`xml`；内部链接须从当前文件相对解析，不能用本机绝对路径；外链用 HTTPS。
- 示例不得含真实密钥、令牌、账号、内网地址或客户信息，使用 `YOUR_APP_ID`、`YOUR_APP_SECRET` 等明显占位符。
- 不堆叠装饰性分隔线、徽章或 emoji；可保留已有风格，新增内容保持克制。

## 新增或重构主文档时

按需采用：模块名与一句话简介 → 依赖与环境 → 功能 → 权限配置 → 快速开始与核心 API → 生命周期、线程及资源释放 → 注意事项与 FAQ → 更新日志。不为空章节占位。

## 涉及 Android 示例时

- 新项目依赖优先 Kotlin DSL：`implementation("io.github.qytech:artifact:1.2.3")`；同时提供 Groovy 时分别标明构建脚本，不混写。
- 持有系统或 Native 资源、监听器、协程时，必须展示或说明释放方法与时机。
- 参数单位写入名称或邻近说明，如 `positionMs`（毫秒）。
