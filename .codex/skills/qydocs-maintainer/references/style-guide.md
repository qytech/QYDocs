# QYDocs 写作规范

## 文风

- 使用简洁、直接、可验证的简体中文。
- 面向 Android 集成工程师说明“做什么、如何接入、有什么限制”。
- 技术标识放在反引号内，例如 `release()`、`arm64-v8a`、`positionMs`。
- 不使用营销式形容词；除非有明确依据，不写“完美”“完整支持”“零延迟”等绝对表述。

## Markdown

- 每个文件只保留一个一级标题，章节从二级标题开始。
- 标题文本不转义普通标点；标题前后保留空行。
- 无序列表使用 `-`，有步骤关系时使用有序列表。
- 代码围栏使用小写语言标识：`kotlin`、`groovy`、`xml`、`java`、`bash`、`text`。
- 内部链接使用相对路径；外部链接使用 HTTPS。
- 不为纯装饰目的堆叠分隔线、徽章或 emoji。可保留已有风格，但新增内容保持克制。

## 版本记录

模块内推荐格式：

```markdown
## 更新日志

### v1.2.3（2026-08-05）

- 新增……
- 修复……
- 优化……
```

- 最新版本位于最前。
- 使用语义明确的动词，单条记录只表达一个可验证变化。
- 破坏性变化、迁移步骤和默认值变化必须单独说明。
- 历史版本缺少日期时保留现状，不推测日期。

## Android 示例

- 新项目依赖示例优先使用 Kotlin DSL：

```kotlin
implementation("io.github.qytech:artifact:1.2.3")
```

- 同时提供 Groovy 时，明确标注两种构建脚本，不混写。
- 示例使用 `YOUR_APP_ID`、`YOUR_APP_SECRET` 等明显占位符。
- 涉及持有系统资源、Native 资源、监听器或协程时，必须展示或说明释放方法与调用时机。
- 参数有单位时写入名称或邻近说明，例如 `positionMs`、单位毫秒。

## 首页同步清单

更新模块后检查根 `README.md`：

- 导航表中的目录链接是否正确。
- Maven Central 的 groupId/artifactId 是否正确。
- 模块简介与当前能力是否一致。
- 导航行“最后更新”是否为本次文档日期。
- 文件末尾“仓库最后更新”是否反映最近一次内容更新。
